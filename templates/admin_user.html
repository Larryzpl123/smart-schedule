That is all this page shows about it — not the contents, not its size, not how many classes or events are in it. Nothing an admin does here needs any of that (verifying, resetting a password and deleting work off the account, not its schedule), and a leaked admin password should not be a way to learn even the shape of somebody's week. Totals and averages, attached to nobody, are on the disk panel of the main admin page.
The schedule is still in the database: this protects against somebody else getting the admin password, not against whoever holds the hosting account. Only end-to-end encryption with each student's own password would do that, and it would make a forgotten password mean permanently lost data.

For when a student cannot log in and the reset email never arrived. A code is first emailed to the admin address; only after you enter it does the password change. That is on purpose — a reset lets an admin log in as the student and read their schedule, so it is tied to a mailbox the admin password alone cannot reach. The old password stops working once the reset completes, and the temporary one is shown once.
